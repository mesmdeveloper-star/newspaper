Reuters · Nov 17 · Export controls

US tightens scrutiny of advanced chips routed through overseas data centres

The US administration announced restrictions on shipments of advanced chips to data centres in Singapore, Thailand, Malaysia, Indonesia and Brazil where authorities see a risk that Chinese firms could access the compute. The policy targets a route that can bypass physical export limits: renting accelerator capacity from a data centre outside China.

Why it matters: cloud providers, GPU lessors and data-centre operators may face more licensing, customer-verification and location-control obligations. This is not just a chip shipment story; it is a change to how compute access is monitored.

Analysis · AI infrastructure economics

Measure AI ROI at the workload level, not by model hype

For each deployment, calculate cost per successful task: model inference, retrieval, tools, retries, human review, data preparation, security and platform operations. Compare this with measurable labour saved, revenue gained, error reduction or cycle-time improvement.

Track: paid usage, gross profit, GPU utilisation, tokens per task, latency, cloud commitments, depreciation, financing and free cash flow. Separate contracted revenue from pilots, bookings and aspirational pipeline.

CYBERSECURITY & GLOBAL THREAT WATCH

Incidents · exploitation · response priorities
FBI FLASH · Nov 13 · AI-enabled intrusions

FBI: ARTEX framework has enabled intrusions reaching privileged access in under three hours

The FBI says threat actors have weaponised ARTEX, an LLM-driven autonomous penetration-testing framework, to automate reconnaissance through data exfiltration. The advisory describes campaigns across finance, government, technology, defence, telecoms, energy and other sectors. It cites attacks involving approximately 67,000 people in South Korea and a ConnectWise Cloud Backup supply-chain compromise affecting more than 2,250 downstream tenants.

Defensive action: patch exposed systems, enforce phishing-resistant MFA, rotate exposed credentials, restrict internet-facing admin interfaces, monitor abnormal identity and API activity, and review supplier access. Use the FBI advisory's IOCs and mitigations for hunting.

Read FBI FLASH-20261113-001 (PDF) ↗
Reuters · Nov 17 · Third-party JavaScript

Optimizely script compromise exposed visitors to malicious code across 178 organisations

Reuters reports that a vulnerability in Optimizely's Experimentation platform was exploited to inject malicious JavaScript into websites associated with 178 organisations, including Zoom, HSBC, Equifax, CNN, Salesforce and IKEA. The observed payload attempted cryptocurrency address substitution, payment-card capture, cookie theft and iPhone exploitation. Optimizely says it fixed the vulnerability and removed injected code; Reuters could not establish whether the attacks succeeded or how many users were affected.

Response: review third-party scripts and tag managers, validate script integrity, apply restrictive Content Security Policy, inspect payment flows and session activity, and follow vendor-specific incident guidance.

TechCrunch · Nov 16 · Vendor breach

Infoblox confirms unauthorised access through a compromised data-migration vendor

Infoblox said attackers accessed certain company information through a compromised third-party data-migration vendor. TechCrunch reported the vendor provided SharePoint migration services; Infoblox said it activated incident response and found no indication that its products, cloud services, software updates or build-and-release processes were involved. Scope and customer impact were not yet clear.

Response: audit vendor identities, delegated permissions, SharePoint access, data exports and migration credentials. Revoke unnecessary access and review logs around the migration window.

TechCrunch · Nov 16 · AI vendor supply chain

Fireworks AI breach exposed data tied to nearly 150,000 Uber drivers

TechCrunch reported that Uber notified 149,346 people after attackers used internal credentials stolen in a breach at Fireworks AI, a provider of access to open-weight models. The exposed records included names, addresses, dates of birth and driver’s licence numbers. Uber said its alerts did not trigger because the attackers used the vendor's own credentials.

Lesson: MFA alone does not neutralise compromised vendor credentials. Use scoped service identities, short-lived tokens, anomaly detection, customer-side audit logs and strict data minimisation.

Google security research · Threat tracking

Developer tooling remains a high-value attack surface

Recent reporting on attacks involving developer extensions, AI coding environments and repository configuration files reinforces a familiar rule: a trusted plugin or repo setting can execute with a developer's permissions. Review extension sources, lock versions, inspect lifecycle scripts and agent configuration files, and isolate untrusted code.

Operational control: treat MCP servers, IDE extensions, coding-agent hooks and CI secrets as software supply-chain dependencies with explicit approval and monitoring.

Executive security checklist

Five actions security teams should prioritise now

1. Review third-party scripts and SaaS vendor access. 2. Rotate long-lived service credentials and enforce least privilege. 3. Patch exposed systems and apply phishing-resistant MFA. 4. Monitor agent, API and cloud audit logs. 5. Test incident response for supplier compromise and stolen tokens.

For AI agents, add tool allowlists, per-agent identities, human approval for high-impact actions, execution logs and a kill switch.

DEVELOPER CORNER

Practical engineering takeaways

1. Lock down agent extensions and MCP servers

Maintain an approved catalogue, pin versions, review permissions, scan package changes and log tool invocations. Enterprise policy should control both plugin source and what each agent can execute.

2. Build local test loops for cloud-dependent code

Use local emulators for fast feedback, but keep integration tests against real cloud services for IAM, networking, quotas, eventual consistency and regional behavior.

3. Design vendor access as a zero-trust boundary

Issue scoped, short-lived credentials; separate migration identities from production service identities; monitor exports; and revoke access immediately when a vendor incident is reported.

4. Instrument the full agent workflow

Trace model calls, retrieval, tool actions, retries, approvals and human corrections. Record cost per completed task, failure reason and business outcome—not just token usage.

5. Make supply-chain security observable

Use Content Security Policy, script allowlists, integrity checks where feasible, dependency pinning, secret scanning and continuous monitoring for third-party JavaScript changes.

6. Test recovery, not only deployment

Exercise backup restores, cross-account snapshot access, KMS recovery, failover, credential rotation and rollback. A backup that cannot be restored under pressure is not a recovery plan.

MODEL & OPEN-SOURCE WATCH

What matters to builders

Model releases and benchmarks

Track new frontier and open-weight releases, independent evaluations, context limits, tool-use reliability, multimodal quality and licensing. Separate vendor benchmarks from third-party results.

Inference stack

Watch vLLM, SGLang, TensorRT-LLM, llama.cpp, quantisation, KV-cache management, batching and accelerator portability. Benchmark on representative workloads.

Embeddings and retrieval

Compare multilingual embeddings, rerankers, hybrid search and graph retrieval against real domain datasets. Measure recall, groundedness, access control and latency.

Local and private deployment

Evaluate open models for on-premise, edge and private-cloud use. Include GPU memory, throughput, operational overhead, patching and model licence obligations.

Agent frameworks

Prioritise durable execution, permission boundaries, tracing, human approvals and deterministic tests over the number of agents in a demo.

Evaluation discipline

Maintain golden task sets, regression tests, red-team cases and cost/quality dashboards. A model upgrade is not a production improvement until it passes your workload tests.
