# Saurabh's AI Daily — Generation Rules

## Daily Developer Corner

Every daily edition MUST include a **Developer Corner**.

For each edition:
1. Search the web for developer-relevant AI releases and announcements from the **previous 7 days**.
2. Prefer primary sources: official release notes, GitHub releases, vendor engineering blogs, SDK/changelog pages, and official documentation.
3. Prioritize:
   - AI SDKs and APIs
   - coding agents and CLIs
   - agent frameworks and orchestration
   - MCP and tool integrations
   - inference/serving stacks
   - open-weight/local AI tooling
   - databases, vector stores and memory systems
   - observability/evaluation
   - sandboxes, deployment and cloud infrastructure
   - multimodal/voice developer tooling
4. Include 3–6 items that are genuinely new or materially changed during the week.
5. Each item must contain: category, release/development title, date when available, a concise practical developer impact, and a source link.
6. Do not recycle an older item merely because it is popular; prefer something shipped or materially updated this week.
7. Refresh this section every day even when the rest of the newspaper is dominated by model/company news.
8. Keep the section factual and avoid ranking tools as “best” or “worst.”

## Model & Open-Source Watch

Every daily edition MUST include a refreshed **MODEL & OPEN-SOURCE WATCH**.

For each edition:
1. Search for **new model releases from the previous 7 days**, and separately check for significant open-weight/open-source model releases, weight drops, major checkpoints, licenses, or materially important model updates.
2. Cover both frontier and open ecosystems. At minimum, check for meaningful releases from OpenAI, Anthropic, Google, Meta, xAI, Qwen/Alibaba, DeepSeek, Mistral, NVIDIA, Microsoft, Xiaomi MiMo, Moonshot/Kimi, Z.ai/GLM, MiniMax and other notable labs when they have a release.
3. Include a release in the daily watch when it is genuinely new or materially updated. Do not repeat an older release just because it remains popular.
4. For each release, include:
   - model/family name
   - provider
   - release date
   - access type (API/hosted/open-weight/open-source where known)
   - key capability or modality
   - concise developer impact
   - direct source/model link
5. Clearly distinguish **new releases** from continuing model-watch items.
6. If there are no meaningful new model releases in the lookback window, say so explicitly and use the space for important open-source model updates instead of inventing a release.
7. Prefer primary sources: official model announcements, model cards, Hugging Face repositories/collections, official documentation, GitHub releases and provider changelogs. Use reputable independent tracking only to discover candidates, then verify against a primary source where possible.
8. Track practical details when available: context window, parameter/active parameter count, modalities, licensing, quantization/inference support, pricing, and tool/agent capabilities.
9. Refresh this section every day and keep historical editions intact in the archive.
10. Do not rank models as “best”, “worst”, “winner”, or “loser”; report documented capabilities and differences factually.

## Daily Generation Flow

Before publishing each daily edition:
1. Search broad AI news across models, agents, developer tooling, security, open source, infrastructure, research, robotics, voice/multimodal and enterprise adoption.
2. Run the **Developer Corner** 7-day release scan.
3. Run the **Model & Open-Source Watch** 7-day release scan.
4. Verify important release claims against primary sources and include direct links.
5. Update the live edition while preserving the dated archive.
6. Make the edition date/time current in the newspaper header.
7. Keep the standalone **“🖼️ Images From Today's AI Coverage”** section removed. Images may still appear inside individual news cards when they materially improve the story.

## Visuals

Do NOT generate or include a standalone **“🖼️ Images From Today's AI Coverage”** section. Images may still appear inside individual news cards when they materially improve the story.
