Today's lead · October 23

AI agents, critical bugs, and the new race to secure software

OpenAI and Poland’s NASK are launching joint research on AI safety and security as reports of agent failures sharpen attention on containment and evaluation. At the same time, AI-assisted vulnerability discovery is colliding with real-world patching pressure across internet infrastructure. Today’s lesson: powerful models need independent evaluation, and exposed software needs disciplined, rapid remediation.

Security is now an end-to-end engineering loop: discover, validate, disclose responsibly, patch, verify, and monitor. For AI agents, the parallel loop is evaluate, restrict permissions, log independently, and test recovery. Neither loop is complete until outcomes are independently verified.

Builder's takeaway

Evaluate independently. Patch what is exposed.

Use independent tests for AI behavior and keep agent permissions bounded. For infrastructure, inventory exposed PHP and self-managed GitLab instances, apply the exact vendor fixes, and review logs for suspicious requests.

Developer Corner

Keep the monitor outside the agent
  1. Separate the control plane. Agent code must not be able to disable its logging, monitoring, policy service or emergency stop.
  2. Enforce least privilege outside the model. Validate every tool call in a trusted policy layer; bind permissions to a task, tenant and resource scope.
  3. Use short-lived, scoped credentials. Avoid provider keys in prompts or files; apply spend caps, rotation and instant revocation.
  4. Sandbox browser and repository access. Treat retrieved content and code as untrusted; restrict network egress and filesystem writes by default.
  5. Make high-impact actions explicit. Require human approval for production deploys, deletion, access changes, payments and external communications.
  6. Log decisions, not just outputs. Record principal, requested tool, arguments, policy decision, result and trace ID in append-only storage.
  7. Test adversarially. Add cases for alert suppression, permission escalation, false completion claims, prompt injection and attempts to alter audit records.
Reference architecture

Intelligence should propose. Policy should authorize.

Scoped identity → policy engine → typed tool request → independent approval → sandboxed execution → result validation → tamper-resistant audit.

Keep the kill switch and credential revocation independent of the model and its tool runtime. A successful demo is not a security test.

PROGRAMMING & TECH STACK RADAR

What changed · October 21, 2026

The stack is not disappearing. The development workflow around it is changing: agents can plan, edit multiple files, call tools, run checks and prepare changes. The competitive advantage is shifting toward good architecture, reliable context, fast feedback loops and strong controls.

1 · Agentic software engineering

From autocomplete to delegated engineering tasks

Give an agent a well-scoped issue, repository context, acceptance criteria and a test command. Let it inspect, implement, run checks and produce a reviewable diff. Keep architectural decisions, ambiguous requirements and production approvals with a human. OpenAI describes using Codex for stale-code cleanup, experiment removal and CI maintenance—not only new feature coding.

OpenAI engineering write-up ↗
2 · Multi-model & agent harnesses

Choose the workflow runtime, not just the model

Agent harnesses now package the loop around a model: context retrieval, tool execution, approvals, retries and state. Multi-vendor IDEs and model-routing options make it practical to use a fast model for routine edits and a stronger one for difficult reasoning. Keep the provider behind an adapter and benchmark quality, latency and cost per successful task.

3 · Spec-driven development

Put requirements and acceptance tests before code generation

Keep a concise task spec, constraints, data model, API contracts and acceptance criteria in the repository. Use AGENTS.md or task-specific skills for durable instructions, but avoid giant prompts that bury the important rules. Review and trim old instructions as models and workflows improve.

4 · MCP, tools & skills

Give agents structured access to systems

MCP and reusable skills make tools and domain knowledge available across compatible agents. Use typed, narrow tools for business operations; expose read-only discovery before write actions; validate every argument and permission on the server. Google’s Data Agent Kit brings its data products to several coding agents through MCP tools and skills.

5 · Verification becomes the loop

Tests, static analysis and CI must run during the task

Ask agents to run focused tests, linting, type checks and security scans, then show the actual results. GitHub's agentic autofix for code-scanning alerts now explores code, proposes a change, reruns CodeQL and opens a draft pull request for review. Availability is limited to eligible GitHub Enterprise security customers.

6 · Runtime, observability & security

Agents need production-grade boundaries

Use isolated worktrees or sandboxes, least-privilege credentials, bounded retries, timeouts, idempotency and trace IDs. Keep policy enforcement, audit logs and emergency revocation outside the model's control. Long-running work should persist state durably and resume safely after failure; do not rely on a single giant prompt or in-memory conversation.

Recommended practical stack · for a new AI-enabled SaaS

Keep the proven stack; upgrade the engineering workflow.

Web & API

Next.js / React + TypeScript for the product UI; FastAPI for Python-heavy AI, data and async services. Use Node/NestJS where it already fits the business domain—avoid splitting services without a real boundary.

Data & background work

PostgreSQL as the source of truth; pgvector when semantic retrieval is needed; Redis + a durable job queue for background tasks. Persist agent runs, tool events, checkpoints and approval state.

Agent integration

Use a provider adapter/model router, an agent harness or graph for multi-step workflows, and MCP where interoperable tools add value. Start with one well-defined agent; add multi-agent coordination only when independent roles improve measurable outcomes.

Quality & delivery

Use Docker, CI, unit/integration tests, type checks, linting, dependency scanning and pull-request review. Run agents in isolated branches/worktrees and make them return a diff, test evidence and unresolved risks.

Observability & policy

Capture traces, tool inputs/outputs with secrets redacted, token/cost metrics, latency, retries and success rate. Enforce authorization in deterministic code; keep secrets in a vault and sensitive actions behind approvals.

How to measure the change

Track accepted PRs, task completion rate, escaped defects, review time, rollback rate, cost per accepted change and time-to-recovery. Compare against a baseline before expanding agent autonomy.

Architecture principle: model proposes → policy authorizes → tools execute → tests verify → human reviews → CI deploys. Never let an agent self-approve its permissions or directly bypass release controls.

Stack verdict: Do not switch languages or frameworks simply because AI is popular. The biggest near-term return comes from making your existing codebase easy for agents to navigate: clear modules, stable APIs, small tests, reproducible environments, concise repo instructions and fast CI. Choose a new framework only when it solves a real product or operational problem.

What to watch next

Five questions for every agent in production

  1. Can it disable, rewrite or bypass the controls monitoring it?
  2. Can credentials be revoked without cooperation from the agent?
  3. Can you reproduce every high-impact action from the audit trail?
  4. Are AI-generated security findings deduplicated and reproducible?
  5. Do model and package licenses permit your intended commercial use?

Bottom line: Capability creates value only when authority is bounded, failures are visible and recovery is independent.
